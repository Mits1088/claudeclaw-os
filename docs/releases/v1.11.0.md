# v1.11.0 Upgrade Brief: new models, refreshed dashboard

A focused update shortly after v1.10 brings the latest model choices, a refreshed dashboard, and smoother Telegram controls. Six merged PRs make up this release.

## What changed

The dashboard brings agent workspaces, settings, and appearance together, with guided provider setup and OpenRouter model discovery. Open it with `/dashboard` in Telegram. Telegram's Dashboard Link button copies the login link for pasting into your browser.

Claude now supports live steering alongside the existing Codex App Server implementation. If you message an agent during its turn, Telegram asks whether you meant to steer that turn; `/steer <message>` remains available directly. Steering remains opt-in; ordinary messages stay queued. A late `/steer` becomes a normal follow-up when the turn has ended, and acceptance receipts read simply “Steering update accepted.” Acceptance confirms delivery, not completion of the requested direction.

The catalog adds Claude Opus 5.5, GPT-6 Sol, and GPT-6 Luna. Older supported models remain available; existing explicit model selections remain intact. Unconfigured defaults use Opus 5.5 and GPT-6 Sol. Opus 5.5's effort selector is Default (medium). Provider account access still determines which models you can use.

## Upgrade notes

Follow the project's supported upgrade process: preserve your configuration and local changes, stop services before replacing dependencies, update to the release, install its locked dependencies, build, then restart. Check the dashboard and send a short message to each provider you use.

This update includes Anthropic Agent SDK 0.3.280 with its bundled Claude Code 2.1.280, and Codex SDK/CLI 0.156.1. Updating only your global Claude CLI does not update ClaudeClaw's bundled harness. The new Anthropic harness is required for Opus 5.5.

SDK remains the default Codex transport. The existing native Windows App Server process-tree cancellation limitation remains; this release does not claim that gate is resolved.
