# v1.10.0: shared knowledge, live direction, dependable delegation

ClaudeClaw v1.10.0 gives your agents a shared place to keep useful knowledge, lets you redirect an active Codex conversation, and makes one-shot work easier to schedule and supervise. It also brings GPT-6 Astra into the model controls and fixes failures that could lose a handback, strand a gather, block an agent at startup, or break a file delivery.

This release contains 18 merged PRs since v1.9.0. The highlights below describe the final implementation, including the decision to remove the experimental Crew workflow engine and keep the simpler mission system.

## Highlights

### Give your agents a knowledge base you can edit yourself

The new Obsidian integration lets agents read, write, append, search, list notes, and work with daily notes through a common interface. Your knowledge stays in Markdown files in a vault you control. Enable it from **Settings > Knowledge (Obsidian)** and choose the folders each agent can use.

You can use an existing local vault without Git, or enable Git sync to share it with another Obsidian client. Reads and writes have separate folder permissions. Concurrent writes are serialized, appends use the latest synchronized note, and conflicts are preserved for inspection instead of silently discarding a competing edit.

The feature is off until you enable it. Agents without vault access are not offered the vault tools. [PR #152](https://github.com/earlyaidopters/claudeclaw-os/pull/152)

### Redirect Codex while it is working

With steering enabled, send `/steer Focus on the Windows startup failure first` during an active Codex App Server turn. ClaudeClaw sends the direction to that exact turn without starting a replacement conversation.

Ordinary messages still wait their turn. Delivery feedback distinguishes accepted input, a known failure that becomes a queued follow-up, and uncertain delivery that must not be replayed automatically. Accepted means the provider received the direction, not that the model has already acted on it.

This first slice is opt-in, Telegram-only, and requires Codex App Server. Claude steering remains in separate PR #167 and is not included. [PR #288](https://github.com/earlyaidopters/claudeclaw-os/pull/288)

### Put a one-time task on the clock

Mission tasks now accept a future execution time. Ask for one piece of work at a particular time without creating a recurring job or leaving a fake cron entry behind.

The availability time is persisted in UTC. Mission Control shows the local run time and a countdown, and the scheduler claims the task after that gate opens. Existing immediate tasks work as before; normal completed-task retention still applies. [PR #265](https://github.com/earlyaidopters/claudeclaw-os/pull/265)

### Choose GPT-6 Astra for an agent

GPT-6 Astra is available in the native OpenAI model catalog, dashboard, and Telegram shortcut `/model astra`. Both Codex transports use the pinned 0.153.2 runtime and validate the model's supported reasoning choices. Account availability is determined by OpenAI; selecting a model in ClaudeClaw does not grant access to it.

SDK remains the default transport. App Server remains an explicit choice for its persistent connection and steering support. [PR #267](https://github.com/earlyaidopters/claudeclaw-os/pull/267)

### Make background work easier to trust

Native headless workers again run through the existing supervisor, without requiring a chat account or Docker. Activation and restart wait for a current worker lease, rather than treating a launched process as proof that the worker is ready. Stale instances cannot steal a current lease or complete another instance's claim.

The mission system also closes a crash window: the final child's result and its gather release now commit together. A process exit between those operations can no longer leave a newly completed gather waiting indefinitely. Duplicate handbacks and continuation edges are guarded, and interrupted execution is not blindly replayed.

These are trusted local workers with host access, not isolated sandboxes. [PR #290](https://github.com/earlyaidopters/claudeclaw-os/pull/290), [PR #287](https://github.com/earlyaidopters/claudeclaw-os/pull/287), [PR #280](https://github.com/earlyaidopters/claudeclaw-os/pull/280)

## Reliability and protection

- **Files arrive correctly in Telegram.** Outbound sanitization preserves grammY's upload objects and buffers instead of breaking file delivery while processing captions. [#281](https://github.com/earlyaidopters/claudeclaw-os/pull/281)
- **Configured secrets are protected consistently.** The text policy reads protected values from the configured `.env` as well as process variables. Application diagnostics use the same protected-value policy, including supported encoded forms. This covers application text boundaries, not attachment contents or every child process's output. [#284](https://github.com/earlyaidopters/claudeclaw-os/pull/284), [#286](https://github.com/earlyaidopters/claudeclaw-os/pull/286)
- **Session summaries stay bounded.** `/newchat` summary handling and memory extraction avoid unbounded session summaries. [#274](https://github.com/earlyaidopters/claudeclaw-os/pull/274)
- **Agents start through the right messenger.** All service entrypoints use the messenger dispatcher, and transport preflight owns credential validation. Existing macOS per-agent upgrade instructions now explain how to update the installed service without creating a duplicate main agent. [#272](https://github.com/earlyaidopters/claudeclaw-os/pull/272), [#282](https://github.com/earlyaidopters/claudeclaw-os/pull/282), [#283](https://github.com/earlyaidopters/claudeclaw-os/pull/283)
- **Targeted dependency patches.** Compatible updates address identified issues in Hono, js-yaml, fast-uri, qs, DOMPurify, and development dependencies. This is not a claim that every dependency advisory is resolved. [#285](https://github.com/earlyaidopters/claudeclaw-os/pull/285)
- **Tests stay out of your real service directory.** Agent-creation tests no longer write a launchd plist into the user's actual LaunchAgents folder. [#276](https://github.com/earlyaidopters/claudeclaw-os/pull/276)

## What happened to Crew workflows?

The generalized Crew coordinator and automatic provider recovery machinery were introduced on `main` and then removed before this tagged release. The final product retains ordinary one-shot missions, explicit handbacks, gather/join, and bounded self-continuation. It does not ship an autonomous delegate-assess-delegate loop or automatic provider failover.

The generated changelog includes both the original work and its rollback because it records history. Do not interpret those original feature entries as features present in v1.10.0. PR #290 subsequently restored native headless execution under the trusted-local model; the earlier isolation-only startup restriction is superseded.

If you tracked intermediate `main` builds, historical workflow tables and rows are preserved. Legacy workflow-linked tasks are kept out of ordinary task claiming. The release does not delete that history, replay those workflows, or repair already-stranded historical gathers automatically.

## Upgrade

Use Node.js 22 or 24 LTS. The release CI runs on Node 24.

1. Finish or inspect active work, then stop all main and agent processes before replacing the build. Back up configuration, vault data, and the database using a SQLite-aware backup, or with all writers stopped.
2. Download or check out **v1.10.0**. Preserve your local configuration and any runtime overlays.
3. Install dependencies including development dependencies: `npm install --include=dev`.
4. Run `npm run migrate`.
5. Run `npm run build`.
6. Restart the main process, then the agent processes, and verify conversations, file delivery, and a small mission handback.

Do not run an old Crew-era scheduler alongside the new build against the same database. The migration registry has not gained a v1.10 entry; the standard migration step still handles any outstanding earlier migration. Database schema initialization remains part of normal application startup.

Existing services that launch `dist/index.js` must use `dist/main-entry.js` to select the intended messenger. Rebuilding alone does not update installed service definitions. Preserve the existing service's paths, agent arguments, environment, and logs. Follow the [current service upgrade instructions](https://github.com/earlyaidopters/claudeclaw-os/blob/v1.10.0/README.md), including the macOS per-agent procedure. Re-running the setup wizard can create a duplicate single-instance main service.

### Optional: configure an Obsidian vault

In **Settings > Knowledge (Obsidian)**, set the vault path and choose whether to use Git sync. Then enable the feature and give each participating agent an explicit scope in `agent.yaml`, for example:

```yaml
obsidian:
  folders:
    - Shared/
  read_only:
    - Reference/
  write_folders:
    - Shared/
    - ClaudeClaw/
```

`folders` and `read_only` grant read access; `write_folders` grants write access. Include the daily-note destination in the write scope if that agent should create daily notes. With Git sync disabled, the integration operates on the local folder without issuing Git commands. Git sync requires a usable Git installation and access to the configured vault repository.

### Optional: enable Codex steering

```dotenv
CODEX_TRANSPORT=app-server
MIDTURN_STEERING_ENABLED=true
```

Restart affected processes after changing these settings. During an active Codex turn, send `/steer <direction>`. SDK and unsupported providers report steering unavailable; use an ordinary message for a queued follow-up. `/stop` and `/newchat` remain separate controls.

### Optional: schedule one future mission

```powershell
node dist/mission-cli.js create `
  --agent research `
  --title "Morning review" `
  --at "2026-09-21T09:00:00-06:00" `
  "Review the overnight findings and return a concise report."
```

Use an existing eligible agent and a future RFC 3339 timestamp with an explicit offset or `Z`. This makes the task eligible at that time; execution still depends on the agent and scheduler being available. Recurring work still belongs in `schedule-cli`.

## Known limits

- **Steering is an opt-in first slice.** It is not enabled automatically and does not provide Claude support or live voice. Device/provider acceptance is separate from protocol and unit-test coverage.
- **Native Windows App Server cancellation remains limited upstream.** The pinned-runtime probe could not terminate sandboxed Windows command processes through the protocol. SDK remains the default and rollback path; steering does not remove that limitation.
- **Astra access varies by account.** The earlier checked-in account probe encountered an upstream entitlement rejection. The model integration does not promise access for every subscription or API account.
- **Headless execution trusts the host.** It is not an OS isolation boundary. Automatic crash relaunch while main stays running, and stronger enforcement of identity/delegation restrictions across all entrypoints, remain follow-up work.
- **Protected text may arrive at completion.** The outbound stream guard buffers accumulated provider text before releasing sanitized output, preventing secrets split across chunks from leaking. Attachment bytes and direct tool network traffic are outside that text guard.
- **Dependency work remains.** The dependency review identifies a remaining WhatsApp/browser-download archive dependency chain and separate Vite/Vitest and Python War Room upgrade work. Consult the [security review](https://github.com/earlyaidopters/claudeclaw-os/blob/v1.10.0/docs/v110-dependency-security.md) and current repository advisories; targeted patches are not an all-clear.
