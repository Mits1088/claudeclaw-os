## Dependency review

A fresh full npm audit and production-only audit each report five high-severity affected packages,
zero moderate, zero low, and zero critical. All five are the existing
`whatsapp-web.js -> puppeteer / puppeteer-core -> @puppeteer/browsers -> extract-zip`
chain. No blanket update or forced downgrade was applied during release preparation.

The repository's open Dependabot inventory also includes Vite/esbuild, Vitest
(including a critical advisory), and Python pipecat-ai advisories. Npm's
production-only counts are not an all-clear for the repository. See the
[dependency security review](../v110-dependency-security.md) for exposure and the
separate upgrade work. The release notes disclose these limits.

Release-time `npm explain` review covered ws, protobufjs, @protobufjs/utf8,
axios, basic-ftp, form-data, @modelcontextprotocol/sdk, dompurify, fast-uri,
brace-expansion, and postcss. Their consuming parent requirements still allow
older versions than the protected floors (Monaco pins DOMPurify 3.2.7), so the
existing protections are retained. No dependency version changed in this release
metadata PR. The lockfile retains Windows, macOS, and Linux optional binaries for
esbuild, Rollup, and Codex.

## Runtime and publication gate

At preparation time, the checked-in acceptance records still require actual
runtime validation. Local tests and CI do not establish live provider or device
behavior. Record runtime evidence before publishing the tag and GitHub Release:

- Claude and Codex replies, application diagnostics, and file delivery through the
  intended messenger, including the retained outbound protection boundary.
- An ordinary mission and handback; a gather completing without stranding its join.
- Authorized native headless activation, ready lease, bounded task, and handback.
- Obsidian activation and scoped read/write in a disposable vault; Git sync from
  a second client if that mode is being accepted.
- If enabling steering, an active Codex App Server turn with `/steer`, normal FIFO
  follow-up, `/stop`, `/newchat`, and unsupported SDK behavior.

Existing operator evidence: on September 16, Mike reported that a couple of
Telegram steering commands worked successfully. This establishes the live happy
path for #288, not exhaustive finish/cancel races or a combined final-build smoke.

Obsidian and steering default off. Native Windows sandboxed App Server command
cancellation remains an upstream limitation, not a passing acceptance check.
No public community post is authorized by a request to craft a draft; Naomi's
EAI post remains a separate reviewed publication action.
